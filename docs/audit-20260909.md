# Calib study audit — 2026-09-09

Audited `CalibStudy.cc` and its Condor wrapper for the normalized
`prod_20260908_TTtoLNuCB_syst` and `prod_20260908_TTtoLNu2Q_syst` productions.
The starting branch was `gen-jet-idx-port` at `d62b8d5`, with existing uncommitted
changes that select the up-type W jet through `GenHadQ2JetIdx`. Those changes
are retained.

## Corrections

- Open every input tree before chaining it. The default ROOT chain registration
  could accept a nonexistent file. Check file schema consistency and event read
  success, and reject duplicate input paths.
- Reject non-finite values read by the studies, fractional or out-of-range jet
  assignments, repeated assigned slots, and invalid trigger-lepton charges used
  in charge plots. Previously a non-distinct assignment was counted but still
  entered the plots.
- Reject mixed weighted/unweighted partials and incompatible bin edges or labels.
  Previously mixed weights only produced a warning, and equal bin counts could
  conceal different axes. Require matching `--Vcb` settings.
- Include score=1 in the last visible ParT/PNetB bin. Quote the actual inclusive
  cut `score >= 0.5`; exclude invalid overflow from that yield. Preserve negative
  bins when setting plot axes and report negative out-of-range yields as well.
- Save `histograms.root` before normalization changes the plotted PNetB contents.
  Require new partials with the format marker `meta_format_v2`.
- Cache scalar leaf lookups and refresh the cache when the chain changes files.
  A production-file smoke run fell from 70.49 s to 0.95 s wall time (69.32 s to
  0.68 s user CPU). All 54 shared histogram contents and squared weight sums
  agreed exactly before and after caching. Peak memory was about 325 MiB.
- Correct the plot suffix to “post processor” and update stale README claims.

## Physics behavior retained

1. Start with every event in the processed `Events` tree. Use `finalWeight` if
   present throughout the input, otherwise unit weights. No systematic branch
   or extra scale factor is applied by this program.
2. Require at least four saved jets with pT >= 20 GeV and |eta| < 2.5.
3. Require all four `Gen*JetIdx` assignments to point at saved jet slots. Missing
   matches (`-1`) are a normal cut rejection. Distinctness is an invariant of
   the processor and is now enforced, including events below the four-jet cut.
4. Fill hadronic W and top masses from the assigned corrected jet four-vectors.
   Fill charge and PNetB scores in the six documented pT regions.

`GenQ1` is down-type and `GenQ2` is up-type in the processor. Studies 9–10 use
Q2 directly, retaining both u and c jets for the inclusive sample. The WB plots
select |PDG ID|=5 among the W daughters. Their inclusive-sample population must
be read from the data; the code does not assume it is zero.

The four jets counted above 20 GeV need not be the four matched jets. The mass
plots therefore can use a matched jet between 15 and 20 GeV; the tagger plots
have no pT bin for it. This selection has not been tightened during the audit.

## Validation and limits

`python3 tests/test_calib_study.py` runs small ROOT fixtures in the CMSSW runtime.
It checks cutflow counts and signed yields, score endpoints and sentinels,
u/c inclusion, the matched-jet threshold behavior, malformed inputs, and
split/merge agreement in bin contents and squared weight sums.
All nine tests passed. An independent NumPy/uproot calculation also agreed with
the cutflows and all 50 physics histograms, including squared weight sums, on
four production files spanning both samples (141,902 events).

This remains a physics study, not a complete NanoAOD validator. It does not
recompute calibrations, MET, truth matching, or second-pass normalization, and
it reads only the branches its studies use. Production schema/weight validation
is provided separately by `Calib_ChargeTagger_JH/condor/scripts/validate_processed.py`.
Sentinel tagger scores are kept in underflow and excluded from visible shapes.
Signed weighted purity estimates need not behave like binomial probabilities.

Study 12 (four jets, three XT tags, and charm-candidate delta-R) has no code and
is explicitly marked unimplemented. This audit does not add that new selection.

The manual merge command sums all partials in a directory; it does not prove
that they cover an input manifest exactly once. Use a fresh directory and verify
the partial count and initial event count against the production. The Condor
wrapper clears old partials when a tag is reused, so do not resubmit an active tag.
Full branch-schema comparison applies within each map input chain. Across map
jobs the merge checks histogram compatibility and weight availability; it does
not compare the complete input-tree schemas. The new productions already passed
the processor's campaign-wide output-schema and normalization checks.

## Full production results

Input manifests contain every new production ROOT file exactly once. All map
partials are present, initial event counts and weighted yields agree with the
production summaries, and all final histogram contents and variances are finite.
No duplicate truth assignments were found. Each output has 38 PDFs and
